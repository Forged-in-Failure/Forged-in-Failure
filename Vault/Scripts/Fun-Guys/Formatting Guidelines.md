### Purpose

This is the “house style” for Forged in Failure.

It’s here so when you add a new class, enemy, quest, or lore note, it doesn’t feel like it came from a different game (or a different mood). Think: same bones, same rhythm, even when the ideas get weird.

---

### The vibe we’re writing toward

- Dark, sharp, a little strange.
- Funny is allowed.
- Hope exists, but it’s something the player earns.

---

### The golden rule: make it easy to scan

If a page looks like a wall, it won’t get read.

- Break big topics into sections.
- Use short paragraphs.
- Prefer bullets when you’re listing facts.
- Use dividers to create “beats” the reader can follow.

---

### Headings (so everything has a spine)

Use headings to give every page the same skeleton:

- Overview: what it is, why it matters.
- Details: the useful stuff.
- Notes / TBD: unfinished thoughts, open questions, future hooks.

If a page has multiple concepts, give each one its own divider so it breathes.

---

### Metadata (keep the labels quiet)

When you’re listing facts, keep the label subtle (gray) and let the important word stand out.

Good labels to reuse:

- Genre
- Core themes
- Setting
- Tone
- Type
- Scale
- Temperament

Consistency is the point. Don’t reinvent labels unless you need to.

---

### Two-column layout (words on the left, art on the right)

When a concept has art, use the same pattern every time:

- Left side: the structured description.
- Right side: the image + the artist credit.

If you have multiple images, stack them neatly. One clean gap between them is enough.

---

### Game Concepts (mechanics, enemies, phenomena, items)

Aim for: bold name, one-line hook, then a few clean bullets.

Suggested bullet labels:

- Overview
- Gameplay
- Attacks
- Weak spot
- Drops
- Type / scale / temperament / perception (for creatures/phenomena)

The goal is to capture the idea fast. If it needs depth, add one short paragraph after the bullets; not five.

---

### Scripts (quests + dialogue)

Scripts should read like something a player could click through.

At the top, add a simple two-column header:

- Voice actor info on the left
- Writer info on the right

- NPC lines: in quotes.
- Player lines: clearly marked as “You:” (blue is fine).
- Choice prompts: show the options on one line (Accept / Decline) and keep them visually quieter.
- If you want the choices to feel like buttons, put Accept on the left (green) and Decline on the right (red).

Use dividers like scene cuts:

- intro
- choice
- branch
- turn-in

When the player comes back with the objective:

- Drop a short “Quest Complete” marker.
- Let the player confirm (“I’ve got it.”)
- Let the NPC react (make it character, not just a transaction).
- Then show the reward (coins/item/XP) as a quiet system line.
- Optional: end with a hint, route, or next thread to pull.

---

### Lore pages

Lore should scale without becoming a mess. Use simple buckets like:

- Places
- Factions
- Creatures
- Beliefs / Myths
- Timeline

Write lore as short paragraphs or bullet lists. Keep it readable enough that you can come back months later and immediately remember what you meant.

---

### Credits page

Credits should be clean and respectful:

- Group by role.
- List names under the role.

If someone has multiple roles, repeat them where they belong. It’s better than making the reader do detective work.

---

### Quick checklist

- [ ] Sections are easy to scan
- [ ] Labels are consistent (and subtle)
- [ ] Art uses the same two-column pattern
- [ ] Dividers separate major beats
- [ ] Scripts clearly separate NPC / player / choices
- [ ] Rewards + system lines stay visually quieter
